# 秒杀链路压测报告（容量拐点）

**环境：** macOS 本地，Spring Boot `loadtest` profile，单实例  
**依赖：** MySQL `:3307`、Redis **宿主机** `:6379`、RabbitMQ Docker `:5672`  
**接口：** `POST /api/interview/booking/seckill`  
**数据：** 600 压测用户，slot **9901** 容量 **500**  
**脚本：** `loadtest/run_seckill_loadtest.py`（每阶段 `reset-loadtest.sql` + **宿主机** `redis-cli FLUSHDB`）  
**日期：** 2026-06-02  

> **说明：** 此前阶梯全 400 的根因是脚本对 Docker Redis 执行 `FLUSHDB`，而应用连的是宿主机 Redis，用户周期锁（600s TTL）未清。已改为 `redis-cli -h 127.0.0.1`；消费成功后会 `clearUserCycleLock`。

## 一、脉冲压测（N 人同时 1 次，每轮 reset）

| 并发人数 | 受理 202 | QPS | P50 | P95 | P99 |
|---------|---------|-----|-----|-----|-----|
| 100 | 100/100 | **174.0** | 512ms | 560ms | **572ms** |
| 200 | 200/200 | 152.3 | 1151ms | 1280ms | 1301ms |
| 300 | 300/300 | **218.9** | 1233ms | 1323ms | 1349ms |
| 400 | 400/400 | 196.4 | 1748ms | 1971ms | 2014ms |
| 500 | 500/500 | 155.5 | 2905ms | 3145ms | 3176ms |

- **500 人抢 500 名额：** 500/500 返回 **202**，无超卖（Lua 预扣 + 异步落库）。  
- **脉冲峰值 QPS：** **≈219**（300 人同时）。

## 二、阶梯压测（固定线程池，500 用户各 1 次，每阶段 reset）

| 并发 | 受理 202 | 错误 | QPS | P50 | P95 | P99 |
|------|---------|------|-----|-----|-----|-----|
| 50 | 500/500 | 0 | 160.3 | 258ms | 679ms | 922ms |
| 100 | 500/500 | 0 | 154.9 | 578ms | 1133ms | 1358ms |
| 150 | 500/500 | 0 | 141.5 | 997ms | 1733ms | 2357ms |
| 200 | 195/500 | **305 超时** | **221.6** | 846ms | 2178ms | 2223ms |
| 300 | 500/500 | 0 | **160.9** | 1671ms | 2976ms | 3048ms |
| 400 | 500/500 | 0 | 143.5 | 2964ms | 3374ms | 3424ms |
| 500 | 500/500 | 0 | 128.3 | 3570ms | 3831ms | 3872ms |

- **峰值 HTTP QPS：** **221.6**（200 并发，但 **61% 连接超时**，不宜作为容量水位）。  
- **峰值稳定受理 QPS（202、0 错误）：** **160.9**（300 并发，500/500 受理）。  
- **200 并发拐点：** 线程/连接池或客户端并发打满，出现大量 status=0；调高 Tomcat `max-threads`、压测客户端连接池后可复测。

## 三、容量结论（单实例本地）

| 指标 | 数值 | 说明 |
|------|------|------|
| **最高脉冲 QPS** | **~219** | 300 人同时 1 请求 |
| **最高稳定受理 QPS** | **~161** | 300 并发阶梯，500/500×202 |
| **最高 HTTP QPS** | **~222** | 200 并发，含超时，不推荐投产 |
| **500 人秒杀** | QPS **~156**，P99 **~3.2s** | 全部 202，业务正确 |
| **保守水位（P99≤800ms）** | **~100 并发 / 100 人脉冲** | 脉冲 100：P99 572ms；阶梯 50：P99 922ms（略超） |
| **可承受并发（全 202、无超时）** | **≤500** | 延迟随并发升高，400～500 时 P99>3s |

**瓶颈：** 单实例 Tomcat + Redis Lua + Outbox/MQ 消费；高并发主要体现为 **排队延迟**，而非大量 4xx。

## 五、复现命令

```bash
# 宿主机 Redis + MySQL 3307，应用 loadtest profile
export LOADTEST_MYSQL_PORT=3307
./mvnw spring-boot:run -Dspring-boot.run.profiles=loadtest

# 脉冲拐点
python3 loadtest/run_seckill_loadtest.py --burst-sweep 100,200,300,400,500

# 阶梯并发（跳过默认 500 脉冲）
python3 loadtest/run_seckill_loadtest.py --skip-burst --concurrency-sweep 50,100,150,200,300,400,500
```

原始 JSON：`loadtest/results-max.json`（阶梯）；脉冲见 `loadtest/run-max.log`。
